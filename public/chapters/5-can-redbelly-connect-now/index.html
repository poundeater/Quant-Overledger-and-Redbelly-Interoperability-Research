Tested

On 19 October 2026 we read Overledger's live network list, which has 59 entries, and its Fusion list, which has 3 T2. Overledger's docs say the live list comes from this call S4S15. No entry in either list mentions Redbelly, and none has chain ID 151 or 153 T2. Every network named in the list is a test network or a private network, including one permissioned Canton network, and none is named as a mainnet T2. The first two Fusion entries are Quant's own private network and Ethereum Sepolia T2.

Tested

The live network entries label each network with key, displayName and dltType, while the docs describe networkId, name and type T2S4S15. The docs and the live service may differ in naming, so field names in this report follow the live output.

Tested

On 20 October 2026 we tried to register Ankr's Redbelly endpoint as a node in our own Overledger account. The request needs a network value and a dlt family S22. Without a network the call failed with "network : Required". With our guessed network name redbelly-mainnet it failed with "Unsupported network - check the RPC URL matches the selected network" T3. The Ankr endpoint itself answered chain ID 0x97 (151) when called directly T4. As a control, a node for Ethereum Sepolia, a network that is in the live list, was accepted and then deleted T3. So the request format worked, and the refusal came at the network step. Redbelly does not appear in the live network list T2, so there was no listed name to copy. We then submitted six plausible names (Redbelly, Redbelly Mainnet, Redbelly Network, Redbelly Network Mainnet, and two testnet variants) on 20 October 2026. All six returned HTTP 400 with the same "Unsupported network" message, and no node was created T5. The identical message for every value means we cannot tell whether the name or the RPC check caused the refusal. This shows that none of these six values was accepted. It does not show that no accepted value exists.

Tested

The docs and the live service differ in four small ways. The reference page lists Bearer credentials and a 201 response for node registration S22, but the same key was rejected as a Bearer token and accepted in the X-API-Key header, and the control registration returned HTTP 200 T3. The reference page also lists eight approved provider domains, adding drpc.live, while the Connectors page lists seven S22S4. Which page is current is Unknown. Last, the reference page does not mark the network field as required, but a request without it was refused with HTTP 400 and a message saying the field is required S22T3.

Tested

On 20 October 2026 (20:30 UTC) we sent one GET request, with no credential, to the /health path of the Overledger service at fusion-rollup.quant.dev, which is the base address in Overledger's API reference S15. The reference lists that path as a liveness check, and its example response shows status "ok" with only status, runtimeVersion and supportedSdkVersions S32. The live service answered HTTP 200 with status "degraded", and its checks list showed trackerPoller as "stalled" and five other checks as ok or connected T8. The checks list is not in the reference example S32T8. This is one call from one location. It describes that service on that date, says nothing about Redbelly, and we do not know what the stalled check means.

Gateway, self-serve (Analysis). Against Overledger's three tests S4: a Redbelly RPC over HTTPS exists S12, and Redbelly is EVM compatible S13, which is a supported self-serve family S4. Whether an endpoint works with an API key alone is Unknown, because Ankr's own terms were not reviewed. Ankr is on Overledger's approved provider list S4 and lists a Redbelly mainnet endpoint S12, so a public node registration looked possible in principle. We tried it and it was refused at the network step, as described above T3. Two doubts remain. Self-serve is described for public networks S4, and writing to Redbelly needs an access credential S14, so how Overledger would classify it is Unknown. And a private node serves only the account that registered it S4.

Gateway, engagement (Analysis). This is the documented path for gated networks S4. Nothing in the docs excludes Redbelly, and nothing says it is accepted. The outcome would depend on Quant. Redbelly publishes public RPC addresses S12, and one of them answered read calls without a credential T6, but an account needs an access credential before it can write S14. That is close to what Overledger's overview calls a public permissioned network S23. No source says Quant would classify Redbelly this way, so which path applies is Unknown.

Fusion Rollup (Analysis). Redbelly is not in the testnet launch list, the docs describe no way for an outside network to be added, and connecting a chain needs bridge and dispute contracts deployed on it S5. The live Fusion list we read has no Redbelly entry T2.
