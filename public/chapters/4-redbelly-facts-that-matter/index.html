4. Redbelly facts that matter

Confirmed

Receptor is Redbelly's native identity and verifiable credential protocol. It facilitates network access and is built on the W3C verifiable credential model S6. Redbelly says issuers who provide network access are accredited S6.

Confirmed

Proof by Query lets a user prove a fact, such as being over 18, to a verifier smart contract without revealing the underlying data on chain S7. In Redbelly's published flow, the business smart contract that verifies proofs is deployed on Redbelly, new issuer state is submitted to a state contract, and the credential's revocation status is checked before the proof is generated S7.

Confirmed

Redbelly's developer portal says Receptor lets a developer program eligibility checks into smart contracts and dApps using verifiable credentials S27. It names two credential types: Proof by Query, which works on chain, and selective disclosure, which works off chain S28. The selective disclosure page says it can only be used off chain S31. Anyone can issue credentials with Receptor's issuer module, and some issuers are accredited by Redbelly governance to issue network access credentials S28. Each developer decides which issuers to trust for their own compliance needs S28.

Confirmed

Redbelly's developer portal says every network participant must prove who they are before gaining access, and that Receptor facilitates this S35. It describes accredited issuers as a special class responsible for helping users and businesses through that process, and says all accredited issuers are listed in an on chain registry S33. The Eligibility SDK page says the SDK checks investor eligibility using Privado ID and the Iden3 zero-knowledge proof ecosystem, and its setup covers a backend verifier service S36.

Confirmed

Redbelly's developer portal lists mainnet chain ID 151 and testnet chain ID 153, each with a public RPC address. For mainnet it also lists two third-party public RPC providers, Ankr and Uniblock, and says Uniblock needs an API key S12.

Tested

A direct call to Redbelly's mainnet RPC on 19 October 2026 returned chain ID 0x97, which is 151, and reported the net_version method as not available on that endpoint T1. The same call on 20 October 2026 gave the same chain ID and the same net_version error, and eth_blockNumber answered with block 3,231,514, with no credential sent T6. A call to the testnet RPC address listed in the developer portal S12 returned chain ID 0x99, which is 153, with the same net_version error T7.

Analysis

The developer portal S12, our own test T1 and the TASK-16 playbook S20 all give 151 for mainnet.

Confirmed

Redbelly says it is compatible with the EVM and can run contracts written for it, with EVM version Prague and Solidity version 0.8.30 S13. Before an account can write to the network, its user must claim an access credential from an accredited issuer and then enable the account through a network smart contract S14. The Eligibility Kit helps RWA issuers check investor eligibility with zero-knowledge proofs S8, and a hook reads on-chain state to check whether an address has permission S9.

Confirmed

Tokeniser is a Redbelly Network project. It says eligibility is programmed into every asset at protocol level and every transfer is checked against the asset's rules S10. Tokeniser's compliance page says identity, eligibility and limits are checked before any trade proceeds, and that a trade that fails a check does not proceed and is logged S25. Its technology page says Tokeniser runs on Redbelly Network and that eligibility is enforced at the point of transfer S26. Its secondary transfer page describes investors exiting between redemption windows by transferring a position to another eligible investor, with the fund's eligibility rules and limits applied automatically to each transfer S37.

Confirmed

Redbelly can already be reached by a third-party bridge. In August 2025 Celer announced cBridge support: USDT, USDC, WBTC and ETH from Ethereum, LQDX from BNB Chain, and RBNT out to Ethereum and BNB Chain, initially as a pegged bridge S11. Redbelly's developer portal lists the same route and says RBNT bridges out from Redbelly to Ethereum and BNB Chain, not back S30. The portal also lists tokens that can be bridged between Redbelly and other chains through LayerZero, using Stargate, with the Oku bridge page as the interface S29. It lists a third route, Lucid Labs, powered by Polymer and LayerZero, for tokens that can be bridged between Redbelly and other chains S34. These routes are independent of Quant.

Confirmed

A community testnet bridge from the Task Board lets a user lock Sepolia ETH and receive wrapped WETH.rb on Redbelly testnet, and the page's own description calls it a 2-of-3 relayer scheme S16. A second community repository says that, as of July 2026, LayerZero, Axelar, Wormhole and Connext had no testnet deployment on Redbelly, and that LayerZero was live on Redbelly mainnet only. These are that author's findings and were not checked by us S17. Redbelly's own developer portal now lists a LayerZero route S29. The same repository describes its own bridge as a trusted-relayer design for testnet use, where whoever holds the relayer key can mint S17.
